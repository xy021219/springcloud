## 目标

浏览器里的页面和 Java 接口继续分成两个进程。未登录不能改表；登录后可以改表，也可以退出、重置密码。

## 范围

现有目录已经分开：`frontend/` 是页面，`backend/` 是接口，开发时由 Vite 把 `/api` 转到 `8080`。这次不把页面打进后端，不加注册、角色、权限、邮件。

要改：

- `backend/`：Spring Security，接口改为校验 `Authorization: Bearer`。密码用 BCrypt。令牌用 Spring Security 自带的 JWT，不另加 jjwt，也不做刷新令牌。
- `frontend/`：登录页、表格页、重置密码页。令牌放在 `sessionStorage`。
- `.gitignore`：忽略开发库文件 `backend/data/`。

不做什么：

- 不发重置邮件。本机没有邮件服务。
- 不加用户注册、角色和管理员。
- 不改表格的列规则和 5 MB、500 行、50 列限制。

鉴权做法看过两个现成实现，都不把代码搬进来：

- [hendisantika/spring-boot3-jwt-security](https://github.com/hendisantika/spring-boot3-jwt-security/)：Spring Boot 4 的登录示例，还带角色、注册和 Swagger。超出这一版。
- Spring Security 自带 JWT（Apache License 2.0，随 Boot 4.1 发布）：无状态接口，页面和后端可以分开部署。用这个。

## 输入 / 输出

开发库从内存 H2 改为文件 H2：`jdbc:h2:file:./data/sheeteditor`。生产仍用 MySQL 环境变量，不自动建表，配置里仍然不写 `ddl-auto: update`。

用户表（确认前不执行）：

```sql
-- MySQL
CREATE TABLE app_user (
  id BIGINT NOT NULL AUTO_INCREMENT,
  username VARCHAR(64) NOT NULL,
  password_hash VARCHAR(100) NOT NULL,
  token_version INT NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  CONSTRAINT uk_app_user_username UNIQUE (username)
);
```

```sql
-- H2，列与上面相同
CREATE TABLE app_user (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  username VARCHAR(64) NOT NULL,
  password_hash VARCHAR(100) NOT NULL,
  token_version INT NOT NULL DEFAULT 0,
  CONSTRAINT uk_app_user_username UNIQUE (username)
);
```

开发环境在表是空的时候插入一个用户：用户名 `editor`，密码 `editor123`。生产不插入。

接口：

- `POST /api/auth/login`：`{ "username", "password" }`。成功返回 `{ "token", "username" }`。用户名或密码不对返回 401，`用户名或密码错误`。
- `POST /api/auth/logout`：要带令牌。把该用户的 `token_version` 加 1，返回 204。旧令牌再访问接口返回 401。
- `POST /api/auth/password`：要带令牌。`{ "oldPassword", "newPassword" }`。原密码不对返回 400，`原密码错误`。新密码短于 8 位返回 400，`新密码至少 8 位`。成功后更新密码哈希、`token_version` 加 1，返回 204。旧令牌失效，要用新密码重新登录。
- `POST /api/sheets/preview` 和 `POST /api/sheets/export`：没有有效令牌返回 401，`请先登录`。

令牌里带用户名和 `token_version`，有效期 12 小时。退出或重置密码后，版本对不上即拒绝。

页面：

1. 打开先到登录页。登录成功进入表格页。
2. 表格页保持现在的上传、勾选两列、导出。另有退出、重置密码。
3. 重置密码页填写原密码和新密码。成功后清除令牌，回到登录页。

后端允许来自 `http://127.0.0.1:5173` 的浏览器直接调用，不依赖登录 Cookie。

## 验收

1. 不带令牌调用 `POST /api/sheets/preview`，返回 401，正文含 `请先登录`。
2. 用 `editor` / `editor123` 登录得到令牌，再预览一份 3 列 2 行的 `.xlsx`，返回表头和两行。
3. 调用退出后，用同一个令牌再预览，返回 401。
4. 重新登录，用错误原密码重置，返回 400。用正确原密码把密码改为 `editor4567` 后，旧令牌返回 401，新密码可以登录。
5. 页面上走完：登录、上传并导出、退出、用新密码登录、重置密码后回到登录页。
6. 本机不启动 MySQL，上述步骤仍能完成。
