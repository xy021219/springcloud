## 这一轮

在基础秒杀上改成四步：网关验签，注解和切面按请求号防重复，Redis Lua 扣库存，RabbitMQ 异步落库。改表页面和同时 2 份的限制不动。

## 目标

模拟一场库存为 10 的秒杀。同一个用户只能成功一次。库存在 Redis 里用一段 Lua 扣减。签名不对的请求在网关被拒绝。同一个请求号重复提交不会再次扣库存。扣成后把订单发到 RabbitMQ，由消费者写入 ry-cloud。

## 范围

- 网关新增只作用于 `/tool/seckill/**` 的签名过滤器，放在现有登录校验之后
- `ruoyi-tool` 新增幂等注解、切面、Lua 脚本、下单接口，以及消费 RabbitMQ 并落库的消费者
- 本机用 Docker 启动 RabbitMQ，端口 5672。管理界面 15672。不另起 MySQL 或 Redis
- 前端在系统工具下新增一个秒杀页，上面一个抢购按钮和结果文案
- 不引入 Kafka、Sentinel
- 不改改表现有的同时 2 份限制
- 演示密钥会出现在前端代码里。它只拦住改参数和过期请求，拦不住看到源码后自己签名的人

不拷贝外部仓库。扣库存和记下已购买的用户放在同一段 Lua 里。订单消息发给 RabbitMQ，落库靠唯一键挡住重复订单。RabbitMQ 不在 Redis 进程里，所以发消息不能写进 Lua。发送失败时把库存加回，并去掉该用户的已购买标记。参考的是这两个步骤，不是整段代码：[enometsys/flashsale](https://github.com/enometsys/flashsale)、[seckill-lab](https://github.com/joshleeeeee/seckill-lab/blob/main/docs/chapters/v2-redis-stock.md)。

## 输入 / 输出

- `POST /tool/seckill/order`
- 请求头：登录令牌、`X-Request-Id`、`X-Activity-Id`、`X-Timestamp`、`X-Sign`
- 签名原文是 requestId、activityId、userId、timestamp 用换行拼起来，再做 HMAC-SHA256。密钥同时放在网关配置和前端演示配置
- 时间戳距离服务器超过 60 秒，网关返回「请求已过期」
- 签名不对，网关返回「签名不正确」，请求不进入改表服务
- 成功返回「抢到了」
- 售罄返回「已经卖完」
- 同一用户再次抢返回「已经抢过」
- 同一请求号再次提交，返回第一次的结果，库存不变。这一步用 Redis 和自定义注解、切面完成
- `GET /tool/seckill/activity` 返回活动名和 Redis 里的剩余库存

## 落库

Lua 只负责库存和「这个用户已经买过」。成功后，下单接口把订单消息发到 RabbitMQ，然后返回「抢到了」。消费者从队列取出消息，在同一条事务里用 JdbcTemplate 插入 `seckill_order`，并把活动库存减 1。唯一键冲突说明已经插过，确认消息并丢掉，库存不再减。其他插入失败不确认消息，让 RabbitMQ 稍后再投。这个服务要连上 `ry-cloud`。若 MyBatis 因为没有 Mapper 启动失败，再排除 MyBatis 自动配置。

## 验收

1. 先写测试：库存预置为 1 时连续两次下单，第二次必须是售罄或已经抢过。旧实现若两次都成功，测试失败。改完后通过。Redis 没起来不算这次红灯。
2. 同一请求号调用两次，库存只减 1。
3. 签名错误的请求返回「签名不正确」。页面点按钮若当时没走，变更记录写未实测。
4. 消费者处理消息后，`seckill_order` 有对应行。表还没建，或 RabbitMQ 没起来，不算红灯。
